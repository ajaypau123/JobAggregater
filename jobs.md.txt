Build a Python-based Job Aggregation V1 system.

IMPORTANT: This is only the first MVP. Do NOT build a website, dashboard, database, login system, payment system, recruiter system, AI agent, or user authentication.

The only objective is:

APPROVED/FREE JOB API SOURCES → COLLECT JOBS → NORMALIZE → VALIDATE → REMOVE DUPLICATES → EXPORT CSV

### 1. Legal/source requirement

The system must only collect jobs from sources whose API/feed terms permit the intended aggregation/use.

Do NOT:

* scrape websites that prohibit automated collection
* bypass CAPTCHA
* bypass authentication/login
* bypass rate limits
* bypass anti-bot protection
* bypass paywalls
* use proxies to circumvent restrictions
* collect data from restricted sources
* assume that a public webpage automatically permits scraping

Create a source configuration containing:

* source name
* API/feed URL
* permission status
* enabled/disabled status
* notes
* rate limit if known

Only sources with:

permission_status = "APPROVED"

and

enabled = true

may be queried.

If a source cannot be confidently used for this aggregation purpose, mark it as REVIEW_REQUIRED and do not collect from it.

### 2. Initial sources

Start with free/approved job APIs.

Prioritize:

1. Arbeitnow API
2. Adzuna API, if the applicable API terms permit this use
3. Other genuinely free job APIs/feeds that explicitly permit this type of aggregation

Do not add a source merely because it has a public endpoint.

For every source, document:

* source name
* API documentation URL
* usage/terms URL
* whether an API key is required
* known request limits
* permission status
* attribution requirements

If an API requires credentials, use environment variables. Never hard-code API keys.

### 3. Technology

Use:

* Python 3.11+
* requests or httpx for HTTP requests
* pandas for CSV generation
* python-dotenv for environment variables
* pytest for tests

Keep dependencies minimal.

Do not introduce unnecessary frameworks.

### 5. Common job schema

Every source must be converted into the same normalized structure.

Use these fields:

* job_id
* title
* company
* location
* country
* remote_type
* employment_type
* experience
* salary
* description
* apply_url
* source
* source_job_id
* posted_date
* collected_date
* status

Example:

{
"job_id": "generated-unique-id",
"title": "QA Engineer",
"company": "Example Company",
"location": "Bangalore",
"country": "India",
"remote_type": "Hybrid",
"employment_type": "Full-time",
"experience": "2-4 years",
"salary": null,
"description": "Job description...",
"apply_url": "https://example.com/job/123",
"source": "Arbeitnow",
"source_job_id": "123",
"posted_date": "2026-10-08",
"collected_date": "2026-10-08",
"status": "active"
}

If a source does not provide a field, use null/empty value rather than inventing information.

Do NOT use an LLM to guess missing information.

### 6. Source connector architecture

Create a common interface in:

aggregator/sources/base.py

Each source connector should provide a method similar to:

collect_jobs()

The method should return normalized or source-specific job records that can subsequently be passed through the common normalization pipeline.

The architecture must make adding Source 3, Source 4, Source 5, etc. easy without modifying the core aggregation logic.

### 7. Collection process

When main.py runs:

1. Load source configuration.
2. Select only enabled + approved sources.
3. Call each source connector.
4. Collect all available jobs.
5. Handle API errors without crashing the entire process.
6. Record source-level statistics.
7. Normalize all records.
8. Validate records.
9. Remove duplicates.
10. Export the final CSV.

One failed source must not prevent other sources from being processed.

### 8. Validation

Reject jobs that do not contain the minimum required information.

Minimum required fields:

* title
* company
* apply_url
* source

Validate:

* apply_url is a valid HTTP/HTTPS URL
* title is not empty
* company is not empty
* source is known
* source_job_id should be retained when available
* posted_date should be parsed when available

Do not invent missing information.

Keep rejected records in memory during the run and show rejection statistics in the terminal.

### 9. Deduplication

Implement deterministic deduplication first.

Priority:

1. Same source + source_job_id
2. Same normalized apply_url
3. Same normalized company + title + location

Normalize values before comparison:

* lowercase
* trim whitespace
* collapse repeated spaces
* normalize obvious URL variations where safe

Do NOT implement complicated AI similarity matching in V1.

Do NOT accidentally merge two different jobs merely because their titles are similar.

### 18. Definition of Done

The project is complete only when:

1. The application can successfully connect to at least one approved free job API.
2. It collects real job records.
3. Records are converted to the common schema.
4. Invalid records are rejected.
5. Duplicate records are removed.
6. The final records are exported to a CSV.
7. The CSV opens correctly in Excel/Google Sheets.
8. API credentials are not hard-coded.
9. One source failing does not stop other sources.
10. Tests pass.
11. README explains setup and source compliance.
12. Adding another source requires only a new connector/configuration rather than rewriting the core pipeline.

Before adding any new source, explicitly identify its API documentation and applicable usage/aggregation terms. If permission is unclear, do not enable that source.

Build this as a clean, maintainable V1 rather than overengineering it.
